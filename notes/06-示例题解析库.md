# 六、示例题解析库: 把讲解存成能看的东西

第五章把仓库拆成了公开的站点和私有的笔记。这一章讲一件更小的事: 页面上那份「没密钥也能看效果」的演示样例, 我准备往里加题的时候, 顺手核对了一遍题面, 发现它已经对不上了。

## 6.1 起因是那份演示样例其实已经错了

原来 web/sample-explanation.json 里存着一份 A+B 的讲解, 是真的调过一次模型生成后存下来的, 我一直拿它当「没密钥也能看效果」的入口。它里面写着「两个正整数 a 和 b」、「1 ≤ a, b ≤ 100」, 样例是 1 2。

而洛谷现在的 P1001 题面是「两个整数 a,b」, 数据范围 −10^9 ≤ a,b ≤ 10^9, 样例是 20 30。题面换了, 解析没跟着换。演示样例摆在页面上, 懂题的人扫一眼就知道对不上 —— 这不是「过时」, 是「错了」。

所以这次不是「再加两道题」, 而是先把这件事重做一遍: 把样例从「一个文件」升级成「一个库」, 并且让每一道题的解析都对着当下的题面重新生成。

## 6.2 库长什么样

库放在 explainer/samples/, 每道题一份 JSON。字段分四组: id / pid / title / difficulty / summary 是题目身份和一句话说明; problem 是题面纯文本; markdown 是讲解正文, 六个固定小节; meta 是生成信息 —— provider、model、用时、输入输出 token 数、生成时间。

外加一个 index.json, 是清单, 页面拿它列出所有示例题。

放在 explainer/ 下面是有意的。prompt_template.json 和 providers.json 都在那儿, 页面、后端、工具脚本读的是同一份东西。「库如果散在别处, 迟早会有一份是过期的」—— 第五章讲提示词单一真源的时候说过同一句话, 这里直接照着做。

## 6.3 页面上的样子

原来那个「看演示样例」按钮撤了, 功能并进讲解页下面新加的一块「示例题」: 三道题并排列着, 每张卡片上是题号、标题、一句话说明、难度和生成它的模型, 点哪道看哪道。

结果区上面那行 meta 写清楚这是预先生成的: 生成于真实 MiniMax 调用、模型是哪个、用了多久、输入输出多少 token、什么时候生成的。看的人能判断这是什么时候的东西, 而不是以为这是实时调出来的。

## 6.4 加一道新题要几步

第一步, 抓题面, 写一个只含 id / title / problem 的 JSON 放进 explainer/samples/。第二步, 跑 python tools/build_samples.py --only <题号>, 这一步会真的调模型生成解析。第三步, 把生成的 JSON 和重建后的 index.json 一起提交。

index.json 由工具自动重建, 不用手改。加题的力气应该只剩「抓题面」和「跑一次生成」, 其余的由工具兜住。

第二步会花额度, 所以先想清楚值不值。这次三道题加起来, 模型耗时分别是 7.9 秒、17.9 秒、12.6 秒, 输出 token 一共不到五千。换来的东西是: 库里每道题都带着可核对的生成信息, 而且解析对着当下的题面。

## 6.5 抓题面这一环比想象中麻烦

洛谷的题面接口不是给匿名访问用的。GET /problem/P1001?_contentOnly=1 回来的是 302, curl -L 直接报 too many redirects; POST /fe/api/problem/detail/P1001 要登录态, 第四章就记着这个。本机没有洛谷 Cookie, 这两条路都不通。

最后用的是浏览器: 打开题目页, 读渲染后的正文。浏览器有正常的运行环境, 能拿到内容。

但这条路子不能当接口用 —— 它依赖浏览器环境, 换台机器、换个网络未必还能成。题面这种数据, 多存一份在库里是有道理的。

## 6.6 模型不听话, 写了一堆 LaTeX

第一遍生成的解析里公式全是 LaTeX: \(n\)、\frac{10a+b}{19}、\[ ... \]。页面上的 Markdown 渲染器是我自己写的, 没有公式引擎, 这些会原样显示成一堆反斜杠。

两头都补了。提示词加一条: 公式用普通文字写, 别用 LaTeX 语法, 页面没有公式渲染器。渲染器加一层降级: 真碰上 LaTeX, 把定界符去掉, 常见的 \frac、\times、\le 换成能看的样子。

然后三道题重新生成了一遍。第二遍的输出里一个反斜杠都没有。

## 6.7 我的想法

这一轮最有用的不是「多了两道示例题」, 而是发现那个演示样例本来就是错的。

预生成的东西都会过时 —— 模型会更新, 题面会改。所以它必须带着元信息: 什么时候生成的、哪个模型、多久、多少 token, 这样过半年再看到的人知道它是什么。反过来, 不带元信息的预生成内容就是在骗人。第五章说过「一个诚实的降级功能, 好过一个看起来很厉害的假功能」, 这一章是同一个道理的第二遍。

把展示用的东西当成一份数据来管, 加题的成本才能降下来。这是我这轮真正学到的东西。
